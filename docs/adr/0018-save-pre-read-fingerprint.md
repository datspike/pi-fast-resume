# Индекс хранит fingerprint до stream-read

---
status: accepted
---

Перед stream-read worker снимает `size`+`mtime` и именно этот fingerprint сохраняет вместе с разобранными метаданными. Если Pi дописал файл во время чтения, актуальный fingerprint на следующем diff не совпадёт с сохранённым и файл гарантированно будет прочитан повторно. Сохранение post-read `stat` могло бы тихо пометить неполные метаданные как свежие; немедленный retry в цикле отклонён, потому что активно записываемая сессия способна удерживать worker в бесконечной догонке.
