# Поиск по суррогатному корпусу вместо полного текста

---
status: accepted
---

Штатный поиск пикера (`fuzzy`, `re:`, `"phrase"`) в оригинале ищет по `id + name + allMessagesText + cwd`, где `allMessagesText` — весь текст сообщений сессии. Хранить полный текст в нашем индексе мы сознательно не будем: это путь к гигабайтной FTS-базе и деградации TUI, как у `@kaiserlich-dev/pi-session-search`. Решение: при сборке `SessionInfo` подставлять в `allMessagesText` суррогат — `name + firstMessage + cwd`, обрезанный до 4 KB. Родная функция сопоставления `matchSession` используется без правок UI; поиск находит по имени, первому сообщению и пути проекта. Полнотекстовый поиск по содержимому сессий — не задача этого расширения.

## Рассмотренные варианты

- Полный текст в индексе (FTS или просто текстовый столбец) — отклонено: объём базы, сложность инкремента, повторение чужого неудачного опыта.
- Собственный упрощённый поиск вместо штатного — отклонено: теряем `re:` и phrase-семантику без выгоды.
