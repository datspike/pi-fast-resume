# Метаданные только из head/tail, счётчик сообщений приблизительный

---
status: superseded by ADR-0014
---

Историческое решение. Для нового или изменённого JSONL воркер должен был читать только head (до 64 KiB: header, `cwd`, `id`, created, `firstMessage`) и tail с адаптивным окном 64→256 KiB (последняя полная `session_info` для имени). Полный файл не читался и не JSON-парсился, а `messageCount` сохранялся от предыдущей версии индекса как приблизительный.

Решение отменено: pi-autoname и ручное `/name` могут записать последнее `session_info` в середине файла, поэтому head/tail не гарантирует имя, которое показывает штатный `/resume`. Актуальный подход — потоковый metadata-pass в worker thread, ADR-0014.
