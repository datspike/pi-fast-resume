# pi-fast-resume

Расширение pi, ускоряющее resume сессий: оригинальный пикер + фоновый индекс метаданных.

## Язык проекта

**Индекс**:
SQLite-база метаданных сессий (`path`, `size`, `mtime`, `id`, `cwd`, `name`, `firstMessage`, счётчики), которую поддерживает worker thread. Единственный источник данных для пикера в нашем расширении. Живёт в `~/.pi/agent/pi-fast-resume/index.db`; производные данные, пересоздаётся при порче без вопросов.
_Не использовать_: кэш (в обсуждениях допустимо, но канон — «индекс»)

**Воркер**:
Worker thread внутри процесса Pi, который сканирует каталог сессий и обновляет индекс. Main thread никогда не читает session-файлы сам.

**Дифф**:
Проход воркера, при котором читаются только новые или изменившиеся файлы (по паре `size`+`mtime`). Холодный первый проход обходит все файлы.

**Head/tail**:
Стратегия чтения изменённого файла: начало файла (header сессии, `firstMessage`) и конец файла (свежая запись `session_info` с именем). Полное чтение файла не выполняется.

**Сабагентная сессия**:
Сессия, созданная расширением pi-subagents: признак — поле `parentSession` в header файла и имя вида `<тип>#<8 hex>`. По умолчанию скрывается из списка пикера.

**Резюме-пикер**:
Оригинальный компонент `SessionSelectorComponent` из `@earendil-works/pi-coding-agent`, который наше расширение переиспользует без модификации UI.

**Поисковый корпус**:
Суррогатное поле, которое расширение подставляет в `SessionInfo.allMessagesText` для штатного поиска пикера: `name + firstMessage + cwd`, обрезанное до 4 KB. Полный текст сообщений в индекс не попадает сознательно — см. ADR-0001.
_Не использовать_: allMessagesText как «полный текст сессии»

**Тихое обновление**:
Фоновая подмена списка сессий в открытом пикере после завершения диффа (`setSessions`). Пользователь не видит ни блокировки, ни «Loading».

**Открытие**:
Команды `/rf` и `/resume-fast` (алиасы одного обработчика) открывают резюме-пикер. Шортката нет и не планируется до отдельного решения.

**Ленивый воркер**:
Воркер создаётся при первом вызове `/rf` или `/resume-fast` в текущей Pi-сессии и завершается на `session_shutdown`. Между открытиями пикера остаётся тёплым; периодического таймера нет.
