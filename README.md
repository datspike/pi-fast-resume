# pi-fast-resume

Локальное расширение для [Pi](https://pi.dev), которое ускоряет выбор сессии. Оно переиспользует публичный `SessionSelectorComponent`, но берёт список из SQLite-индекса метаданных, обновляемого worker thread. При открытии picker основной/TUI поток не сканирует и не разбирает session JSONL.

> **Статус:** собранный ESM package, проверенный на Linux x64 с Pi `0.84.3` и Node `22.21.1`. Это baseline проверки, а не верхняя граница зависимостей: package не блокирует новые версии Pi. Если несовместимость проявится при загрузке расширения, Pi покажет warning с ошибкой; приложи его к issue.

## Команды

| Команда | Действие |
| --- | --- |
| `/rf` | Открыть быстрый picker для resume. |
| `/resume-fast` | Альтернативное имя `/rf`. |
| `/rf reindex` | Удалить производный индекс и начать его пересборку. |
| `/fork-resume` | Выбрать существующую сессию, создать fork для текущего проекта и переключиться на него. Исходная сессия не открывается. |
| `/fr` | Альтернативное имя `/fork-resume`. |

`/fork-resume` и `/fr` не предлагают текущую сессию: для неё используй штатные `/fork` или `/clone` Pi.

## Как пользоваться

1. Открой `/rf` для продолжения сессии или `/fr` для создания fork.
2. В первом запуске picker появляется сразу; список пополняется checkpoint-пакетами во время построения индекса.
3. `Tab` переключает **Current Folder** и **All**.
4. `Alt+G` до закрытия overlay показывает или скрывает сессии pi-subagents. По умолчанию они скрыты; обычные fork/clone не фильтруются.
5. Остальные сочетания остаются штатными для `SessionSelectorComponent`: поиск, сортировка, rename (`Ctrl+R`) и delete (`Ctrl+D`). Текущая сессия выделена и защищена от удаления.

Picker показывает до 20 строк списка одновременно.

## Установка

```bash
pi install /home/spike/hobby/pi-fast-resume
```

После установки перезапусти Pi или выполни `/reload`.

> Требуется Node `>=22.19.0`: это минимум самого Pi. Верхней границы нет. `better-sqlite3` ставит готовый native binding для вашей Node/ОС/архитектуры либо собирает его локально; если оба пути недоступны, npm или Pi покажет конкретную ошибку binding, а `/rf` не зависнет.

## Что делает индекс

Worker хранит в `~/.pi/agent/pi-fast-resume/index.db` ограниченный набор метаданных:

- абсолютный путь session-файла и `cwd`;
- идентификатор, имя, первую текстовую часть пользовательского запроса;
- время активности, число сообщений и связи parent session;
- fingerprint файла (`size` и `mtime`) для incremental scan.

Полный текст диалогов и FTS не сохраняются. Поиск picker работает по ограниченному суррогату `name + firstMessage + cwd`, поэтому relevance search не эквивалентен поиску по полному журналу.

Новые и изменённые JSONL worker читает потоково. Незавершённые или повреждённые строки игнорируются, поэтому при записи активной сессии метаданные могут быть временно неполными до следующего изменения файла. Невалидные JSONL в список не попадают.

Операции `rename`, `delete` и `fork` намеренно используют API Pi или worker для работы с выбранным session-файлом. Это не относится к быстрому открытию и поиску списка.

## Конфиденциальность и эксплуатация

`index.db` может содержать имена сессий, первую реплику пользователя, абсолютные пути и другие перечисленные метаданные. Считай его приватными данными:

- не добавляй его в git, публичные backup или синхронизацию без осознанного решения;
- `/rf reindex` удаляет только производный индекс, но не исходные session JSONL;
- удаление JSONL из picker’а использует штатное подтверждение Pi; активная сессия защищена.

Несколько Pi-процессов используют SQLite lease, чтобы не начинать одинаковый полный scan. Если другой процесс уже владеет scan, picker использует имеющийся индекс и показывает соответствующий статус.

## Архитектура

```text
/rf или /fr
       │
       ▼
полноразмерный overlay + SessionSelectorComponent
       │                         ▲
       ▼                         │ SessionInfo[]
worker thread ── SQLite index ───┘
       │
       ▼
~/.pi/agent/sessions/**/*.jsonl
```

Worker получает корень session-хранилища из контекста Pi, индексирует архивные и обычные сессии, выполняет checkpoint каждые 25 файлов и ограничивает потоковый разбор десятью файлами одновременно.

## Разработка

```bash
npm install
npm run typecheck
npm run lint
npm test
pi -e ./src/index.ts
```

Тесты используют только synthetic JSONL fixtures. Для ручного performance smoke допустим локальный корпус сессий; его нельзя включать в git или публикуемые примеры.

## Сборка и выпуск

`npm run build` собирает отдельные `dist/index.js` и `dist/worker.js`. Локальный запуск исходника сохраняется для разработки, а package manifest использует compiled entrypoint.

Перед npm-публикацией нужен `npm pack` и чистый install smoke на поддерживаемых ОС/архитектурах. `better-sqlite3` — нативная зависимость: если для Node/ОС нет prebuilt binary и не доступна сборочная цепочка, установка должна сообщить ошибку npm. Это ограничение Node ABI невозможно честно скрыть.
